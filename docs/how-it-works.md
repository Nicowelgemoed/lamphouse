# How Lamphouse and Answer Print work

This is the full technical description of Lamphouse (the DRT) and Answer Print (the standalone film rendering).
Both share one film engine. This document covers what each stage computes, where every number comes from,
which design decisions were made and why, and how the result was tested. The code that implements all of it is in
[`build/`](../build), and every DCTL in this repository is generated by that code.

## 1. Data

**Film stocks.** For each of VISION3 500T 5219, 250D 5207, 200T 5213, 50D 5203 and print films 2383 and 2393, the
following come from Kodak's technical datasheets as digitized by
[spektrafilm](https://github.com/andreavolpato/spektrafilm) (CC BY-SA 4.0):

| Quantity | Meaning |
|---|---|
| Log spectral sensitivity, per layer | How strongly each dye-forming layer responds to each wavelength |
| Characteristic curves, per layer | Developed density vs log exposure (Status M for negatives, Status A for prints) |
| Spectral dye density, per dye | How much light each formed dye absorbs at each wavelength |
| Base density | The film base and, for negatives, the orange mask |

The negative curves are positioned so that log exposure 0 is an 18% grey at normal exposure, where the negative
reaches about 0.7 density above base, the classic Cineon/LAD relationship.

Missing samples at the spectral edges were filled by interpolation. All spectra were resampled to 10 nm,
380–740 nm (37 samples) for the GPU. Against the full 5 nm, 380–780 nm data this changes the final image by at
most 0.22 ΔE2000. Changes to the profiles are listed in [`CHANGELOG.txt`](../CHANGELOG.txt).

**Light sources and observer.** Printer lamp: 3200 K black body behind a Schott KG3 heat-absorbing filter.
Projector: Kinoton 75P xenon lamp. Camera reference illuminants: 3200 K for T stocks, CIE D55 for D stocks.
Colour: CIE 1931 2° observer.

## 2. Input decoding (Lamphouse)

Lamphouse accepts DaVinci WG / Intermediate, ACEScct (AP1), ARRI LogC3 (EI 800) / AWG3, ARRI LogC4 / AWG4,
Sony S-Log3 / S-Gamut3.Cine, RED Log3G10 / REDWideGamutRGB, Panasonic V-Log / V-Gamut, and linear DWG. Each log
curve is implemented from its published specification. The gamut is converted to DaVinci Wide Gamut with matrices
computed from the published primaries (Bradford adaptation for ACES' D60 white). Every decode was checked against
the colour-science library's implementations: worst relative error 7×10⁻⁶. Answer Print takes DaVinci WG /
Intermediate only.

## 3. Capture stage: scene → negative layer exposures

The input image is three numbers per pixel from a camera, not a spectrum, so the engine has to estimate how much
light each film layer would have received. The exposure of layer *c* to a surface with reflectance *R(λ)* under
the stock's rated illuminant *I(λ)* is

&nbsp;&nbsp;&nbsp;&nbsp;*E<sub>c</sub>* = ∫ *R(λ) I(λ) S<sub>c</sub>(λ)* dλ

where *S<sub>c</sub>* is the layer's spectral sensitivity. The camera is assumed white-balanced: a surface's colour
under D65 is what arrives as DaVinci Wide Gamut, while the film sees the same surface under 3200 K or D55. That's
the situation of shooting tungsten stock under tungsten light, or daylight stock in daylight.

Three ways of mapping DWG to *E* were built and tested against ground truth (exposures computed from the real
measured ColorChecker spectra, which none of the methods was fitted to):

| Method | ColorChecker error (log E RMS / max) |
|---|---|
| 3×3 matrix fitted on surface spectra | 0.070 / 0.31 |
| Spectral upsampling (smooth spectrum per chromaticity, Jakob & Hanika style) | 0.085 / 0.26 |
| **Second-order homogeneous polynomial (shipped)** | **≈0.046 / 0.15–0.17** |

The shipped mapping uses six terms per layer: *r, g, b* and the pairwise harmonic means 2*rg*/(*r*+*g*),
2*gb*/(*g*+*b*), 2*rb*/(*r*+*b*). It follows root-polynomial colour correction (Finlayson et al.), but with harmonic
means in place of square roots. Both are degree-1 homogeneous, so exposure scales exactly with light and greys stay
exact. Square roots have infinite slope at zero, which made layer exposure fold back on itself for saturated
greens; harmonic means have finite slope and gave the same accuracy without the fold. Weights are fitted by
least squares in relative (log-like) error on ~1,500 smooth, realistic surface spectra plus two ColorChecker
measurements. They are then scaled so 18% grey gives exposure 1 on every layer.

A very saturated input can drive a fitted exposure negative, which real light can't do. Instead of a hard clamp,
which created visible edges, each layer gets a smooth floor at 0.3% of the pixel's mean exposure:
*E'* = ½(*E* + √(*E*² + 4*f*²)).

## 4. Halation

Light that passes through the emulsion reflects off the back of the base and re-exposes the layers from behind.
It is mostly red by then, because the upper layers and yellow filter have absorbed blue and green. The engine adds
a blurred copy of the red-layer exposure back into the red layer, and 30% of that amount into green:

- Kernel: three bounces, the *k*-th a Gaussian of σ·√*k* with weight 0.5<sup>*k*−1</sup>, where σ = 65 µm × *Halation Size*.
- Sampling: 96 taps importance-sampled from that kernel, so all taps carry equal weight. The spiral is rotated and
  radially jittered per pixel to turn sampling patterns into fine noise.
- Strength: 4.5% of the red exposure for 500T, 4% for the others, times *Halation*. VISION3's rem-jet backing keeps
  real halation subtle.
- Scale: microns on film → pixels via the gauge's frame width (Super 16 12.52 mm, Super 35 24.89 mm, 65 mm 52.48 mm),
  so the halo is the same physical size whatever the resolution.

## 5. Negative development

For each layer, density *D<sub>c</sub>* = curve<sub>c</sub>(log<sub>10</sub>*E<sub>c</sub>* + *exposure*), looked up in
Kodak's curve with Catmull-Rom interpolation over 64 samples (≤ 0.004 density error).

**Push / pull.** Development changes contrast and speed: the log exposure axis is scaled by 1 + 0.12 × stops and
shifted by 0.1 × stops before the lookup.

**Interlayer (DIR coupler) effect.** Colour negative releases development inhibitors that hold back neighbouring
layers. Kodak's curves are measured on greys, where every layer is equally exposed, so the effect is already
baked in for neutrals. The engine models only the difference for colours:

1. Develop once and express each layer's density in log-exposure units, *L<sub>c</sub>* = *D<sub>c</sub>* / γ<sub>c</sub>
   (γ<sub>c</sub> = mid-scale gradient).
2. Shift each layer's exposure by −*a* · ½ Σ<sub>k≠c</sub> (*L<sub>k</sub>* − *L<sub>c</sub>*) and develop again.

On a grey every difference is zero, so neutrals are untouched. On a colour, the more exposed layers hold back the
less exposed ones, increasing separation. Because *L* comes from developed density, the effect fades naturally
in the toe and shoulder. *a* = 0.1 × *Interlayer Colour*; the default 0.3 matches the overall chroma of the
spektrafilm simulator's coupler model on the ColorChecker.

## 6. Grain

Grain is added to each layer's density after development, so it passes through the print the way real grain does:

- **Spatial:** two octaves of smoothed value noise per layer, at a dye-cloud cell of 8 µm × *Grain Size* on film.
  The blue-sensitive layer's cells are 1.35× larger.
- **Amplitude:** σ<sub>48</sub>, the RMS density at a 48 µm aperture, per stock: 500T 0.0055, 250D 0.0041,
  200T 0.0039, 50D 0.0025. The ordering follows Kodak's granularity data; the levels were set by eye. It rises with
  density, × (0.25 + 0.75 √(*D*/1.2)).
- **Resolution consistency:** Selwyn's law says RMS granularity scales inversely with the measuring aperture. Each
  pixel samples max(pixel size, cell size) of film, so per-pixel σ = σ<sub>48</sub> × 48 µm / that size.
- **Motion:** the noise seed includes the timeline frame index, so grain changes every frame.

## 7. Printing

The negative's spectral transmittance is *T*(λ) = 10<sup>−(base(λ) + Σ<sub>c</sub> D<sub>c</sub> dye<sub>c</sub>(λ))</sup>.

The printer is an additive printer, as in motion-picture labs. The lamp is split by dichroics into blue, green and
red bands (smooth edges at 492 and 588 nm), each with its own light valve. Exposure of print layer *k* is

&nbsp;&nbsp;&nbsp;&nbsp;*H<sub>k</sub>* = Σ<sub>b</sub> *g<sub>b</sub>* ∫ lamp(λ) band<sub>b</sub>(λ) *T*(λ) *S<sub>k</sub><sup>print</sup>*(λ) dλ

so the print's own spectral sensitivities, including the intrinsic blue sensitivity of every layer, see the
light exactly as it arrives. Band gains are *g<sub>b</sub>* = 10<sup>*G<sub>b</sub>* + 0.025 × points</sup>. One printer
point is 0.025 log exposure, as in a lab.

**Balance.** For every negative/print pair, *G<sub>b</sub>* is solved so that an 18% grey at normal exposure prints
neutral (D65 after projection) at a visual density of 1.0 relative to the open projector, Kodak's LAD aim.
Printer lights at 0 therefore mean "printed to aim".

## 8. Print development

Print density *P<sub>k</sub>* = curve<sub>k</sub>(log<sub>10</sub>*H<sub>k</sub>*), from 2383 or 2393 curves.

- **Print Contrast** scales log exposure around the grey's print exposure, so mid grey stays put.
- **Bleach bypass:** skipping the bleach leaves developed silver in the print, a spectrally neutral density
  proportional to the image. The engine adds 0.35 × *Bleach Bypass* × mean dye density. A lab prints a skip-bleach
  print lighter to hold the midtones, so printer lights are automatically opened by 3.2 points per unit of bleach
  bypass (solved numerically to keep mid grey constant).
- **Print looks:** *Strong print* adds +0.5 stop push, +1.0 interlayer, ×1.18 print contrast, 0.15 bleach bypass and
  +1 point density. *Bleach bypass print* adds 0.85 bleach bypass and ×1.04 contrast.

## 9. Projection

The print's spectral transmittance is lit by the xenon projector lamp and integrated against the CIE observer
to give XYZ. It is normalised so the clear print base is white (Y = 1) and adapted to D65 with Bradford. Mid grey
lands at about 11.5% of white. Then:

- **Answer Print:** XYZ → Rec.709, P3-D65 or DaVinci Wide Gamut. Colours outside the display gamut are desaturated
  toward their own luminance rather than clipped per channel, preserving hue. Then the display encoding (2.4, 2.6 or
  piecewise sRGB), or a DaVinci Intermediate re-encode that Resolve Color Management reproduces exactly with tone and
  gamut mapping off.
- **Lamphouse:** the display transform below.

## 10. Lamphouse's display transform

The film produces a picture as it looks projected in a cinema: 100-nit white, mid grey at 10–11.5 nits, dark
surround. Lamphouse's job is to show that same picture on other displays.

**Tonescale.** Lamphouse uses a hyperbolic tonescale

&nbsp;&nbsp;&nbsp;&nbsp;*y* = (*L<sub>peak</sub>*/100) · (*x* / (*x* + *s*))<sup>*c*</sup>

with *s* chosen so an 18% grey lands on the mid-grey luminance. The reference curve has a 100-nit peak, 10-nit grey
and *c* = 1.4.

**Retargeting.** The film's display-linear result is converted to Rec.2020 and split into a norm (RMS of the
channels) and ratios. The norm goes back through the reference curve's exact inverse to a scene value, then forward
through the live curve:

- **Peak:** *L<sub>peak</sub>* is the HDR peak for PQ/HLG, 100 for SDR.
- **Mid grey:** the Mid Grey Nits slider, raised for HDR by (*L<sub>peak</sub>*/100)<sup>0.18</sup>, so 15 nits at 1000.
- **Surround:** Dim and Bright multiply *c* by 0.95 and 0.9, lowering contrast around the held mid grey for
  brighter viewing rooms.

At the reference the two curves cancel and the look comes through exactly (verified against Answer Print to
0.002 code value with halation and grain on). The ratios are untouched, so hue and saturation of the look carry
over to every display.

**Gamut and encoding.**

- **SDR:** Rec.709 for Rec.709 2.4 and sRGB 2.2 (pure 2.2 power, as sRGB displays decode). P3-D65 for Display P3
  2.2 and P3-D65 2.6.
- **HDR:** HDR output is limited to P3 inside a Rec.2020 container.
  - **PQ:** encoded absolute, 1.0 = 100 nits.
  - **HLG:** encoded with the BT.2100 inverse EOTF for a display of the chosen peak, with system gamma
    1.2 + 0.42·log<sub>10</sub>(peak/1000).
- **Out-of-gamut colours:** desaturated toward their own luminance in the target gamut, then clamped to the peak.
- **DWG DI for RCM:** display-linear DaVinci Wide Gamut, re-encoded as DaVinci Intermediate, which Resolve Color
  Management reproduces exactly with tone and gamut mapping off.

**Creative white.** After retargeting, the whole image can be re-rendered at a different white: a Bradford
adaptation from D65 to D60, D55 or D50 (CIE daylight chromaticities), applied in Rec.2020. Neutrals then display
at that white's chromaticity on a D65 display. The image is scaled so the adapted white's largest channel stays at
peak in the target gamut (Rec.709 for SDR Rec.709/sRGB and RCM, P3 otherwise): white never clips and its hue is
kept, at the cost of slightly lower overall brightness (×0.96 for D60 to ×0.85 for D50 on Rec.709).
D65 is the identity and leaves the image untouched.

## 11. Looks and plain-language controls

A Lamphouse look is a choice of capture response, print base and process plus small offsets:

| Look | Capture response | Print base | Process | Offsets |
|---|---|---|---|---|
| Classic | Daylight (250D) | Classic (2383) | Normal | |
| Night | Fast Tungsten (500T) | Classic (2383) | Normal | |
| Fine | Fine Daylight (50D) | Deep (2393) | Normal | |
| Soft | Fine Tungsten (200T) | Classic (2383) | Normal | development −0.5, contrast ×0.9 |
| Bold | Fast Tungsten (500T) | Classic (2383) | Strong | |
| Silver | Daylight (250D) | Classic (2383) | Silver (bleach bypass) | |

The Response, Print Base and Process menus override the look's choice. Brightness and the colour balances are
printer points with the sign flipped, so positive means brighter or more of that colour.

## 12. Testing

The DCTL language is close enough to C that each DCTL can be compiled on the CPU with small shims
([`build/tests/harness.py`](../build/tests/harness.py)). That makes it possible to test the shipped DCTL source, not a re-implementation of it:

| Test | Result |
|---|---|
| Answer Print DCTL vs the NumPy model, 8 stock pairs, ColorChecker + random colours over 16 stops | 99% within 0.0025 code value (0.03 worst case, one out-of-gamut colour at near-black) |
| Lamphouse vs Answer Print at the reference display, every look, full frame with halation and grain | ≤ 0.002 code value |
| Lamphouse input decoding vs colour-science, 8 spaces | ≤ 7×10⁻⁶ relative |
| Lamphouse HDR: PQ 400/1000/4000, HLG 1000, grey ramp over 16 stops | Monotonic, roll into peak |
| RCM re-encode round trip | Exact |
| Grain changes between frames | Yes |
| Capture stage vs real ColorChecker spectra (held out) | ≈ 0.05 log E RMS |
| Model vs the independent spektrafilm simulator: grey scale, shadow/highlight crossover, ColorChecker chroma | Consistent |

The harness also mimics Resolve's GPU rule that UI parameters and `TIMELINE_FRAME_INDEX` exist only inside
`transform()`. That catches the error a Metal build reports as "use of undeclared identifier", which Resolve's
quick DCTL check does not.

## 13. What is not physical (yet)

- **Interlayer default:** chosen to match another simulator's overall chroma; Kodak publishes no target.
- **Grain levels and halation strength:** set by eye within Kodak's ordering.
- **Printer bands:** a generic additive printer, not a specific lab's.
- **Camera stage:** an estimate. A camera's three channels can't fully determine a spectrum, so unusual lights
  (narrow-band LEDs, neon) are the least accurate.
- **Not modelled:** scanner, adjacency effects, emulsion MTF/sharpness, gate weave and print-through flicker.
